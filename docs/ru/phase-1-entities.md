# Фаза 1: Первоклассные сущности (Сети, Источники, Офферы, Лендинги)

Фаза 1 вводит первые переиспользуемые бизнес-сущности поверх фундамента Фазы 0
(абстракция драйвера + `EntityRepository` + миграции). Каждая сущность —
**универсальная и data-driven**: вся её конфигурация хранится в бесхемном
JSON-поле `settings`, поэтому нет привязки к конкретной сети, источнику, офферу
или лендингу.

Добавлено пять таблиц, все по стандартной схеме сущностей
(`id, name, group_id, settings, created_at, updated_at`):

| Таблица | Назначение |
| --- | --- |
| `groups` | Папки для группировки любых сущностей. |
| `networks` | Партнёрские сети (шаблон постбэка, маппинг статусов, валюта). |
| `sources` | Источники трафика (маппинг параметров, S2S-постбэк, cost). |
| `offers` | Офферы (payout, капы, связь с сетью, тип редиректа). |
| `landings` | Лендинги (локальная папка / удалённый URL, защита). |

Существующие кампании, клики, фильтры, статистика и постбэки не затрагиваются —
новые таблицы добавляются через нумерованные миграции
(`db/migrations/001`–`005`), поэтому апгрейд установленной системы не стирает
данные.

## Админ-интерфейс

У каждой сущности своя страница в админке, и все они генерируются из одной
декларативной схемы:

- `admin/networks.php`, `admin/sources.php`, `admin/offers.php`,
  `admin/landings.php` — тонкие обёртки: задают `$entityType` и подключают общий
  шаблон `admin/entitypage.php`.
- `admin/entityschemas.php` — **единственный источник правды** для полей формы
  каждой сущности. Добавить поле — это изменение данных в одну строку; код писать
  не нужно.
- `admin/entityapi.php` — один универсальный JSON-эндпоинт, обрабатывающий
  `list / get / save / delete / templates` для всех типов сущностей.
- `admin/js/entityadmin.js` — строит форму из схемы, выводит список записей и
  общается с API.

### Типы полей

Схема (`admin/entityschemas.php`) поддерживает следующие типы полей, которые
автоматически рендерит сборщик форм:

| Тип | Хранение | UI |
| --- | --- | --- |
| `text`, `number`, `textarea` | строка / число | обычные поля |
| `select` | строка | выпадающий список из `options` |
| `checkbox` | bool | переключатель |
| `csv` | массив | поле со значениями через запятую |
| `kvlines` | объект | по одному `ключ=значение` в строке |
| `json` | массив/объект | textarea с сырым JSON |
| `entityref` | int id | выпадающий список другой сущности |

## Шаблоны (préfill)

Популярные сети и источники поставляются как **данные**, а не код, в каталоге
`templates/`:

- `templates/networks/` — `generic`, `everad`, `terraleads`
- `templates/sources/` — `facebook`, `google`, `tiktok`, `propellerads`,
  `exoclick`

При создании новой сущности появляется выбор «Начать с шаблона». Каждый шаблон —
JSON-файл вида:

```json
{
  "name": "Facebook",
  "settings": {
    "param_map": [
      {"alias": "sub1", "token": "sub_id_1", "macro": "{{campaign.id}}"}
    ],
    "cost_param": "cost",
    "note": "..."
  }
}
```

Чтобы добавить новый шаблон, положите JSON-файл в нужную папку — код менять не
нужно.

## Интеграция с воронками (офферы и лендинги в шагах)

Шаги воронки теперь могут ссылаться на первоклассные офферы и лендинги вместо
вручную вписанных URL/папок. В `StepSettings` (`campaign.php`) добавлены два
необязательных, обратно совместимых поля:

```json
{
  "action": "redirect",
  "offers": [12, 15],
  "landings": [3]
}
```

Во время маршрутизации `FlowEntityResolver::expandStep()`
(`entities/FlowEntityResolver.php`) разворачивает эти ссылки в существующие
структуры шага `redirectUrls` / `folderNames`, поэтому остальная часть движка
маршрутизации не меняется:

- **Офферы** → записи redirect URL (label = имя оффера).
- **Удалённые лендинги** → записи redirect URL.
- **Локальные лендинги** → имена папок.

Разворот **аддитивный** (явные URL/папки сохраняются), с дедупликацией и
устойчивостью к удалённым сущностям (отсутствующий id пропускается и никогда не
ломает маршрутизацию). Шаги без ссылок работают ровно как раньше.

## Классы сущностей

Тонкие наследники `Entity` добавляют типизированные аксессоры над `settings`:

- `entities/Network.php` — `currency()`, `statusMap()`, `mapStatus($external)`
- `entities/Source.php` — `paramMap()`, `postbackUrl()`, `costParam()`
- `entities/Offer.php` — `type()`, `url()`, `networkId()`, `payout()`,
  `capDaily()`, `capTotal()`
- `entities/Landing.php` — `type()`, `isRemote()`, `path()`, `url()`,
  `target()`
- `entities/Group.php` — группировка в папки

`entities/Repositories.php` — небольшая фабрика, возвращающая кэшированный
`EntityRepository` на тип сущности и драйвер, например
`Repositories::offers($db->driver())`.
