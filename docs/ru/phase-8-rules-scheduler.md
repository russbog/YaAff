# Фаза 8: Движок правил + планировщик

Фаза 8 добавляет автоматизацию в стиле Keitaro: правила, управляемые данными,
которые запускаются по расписанию, проверяют условия по метрикам за окно отчёта
и выполняют действия (пауза/возобновление кампании, коррекция весов потоков,
выгрузка отчёта, обновление блэклистов, …). Всё настраивается данными — правило
является первоклассной сущностью, а его расписание, условия и действия хранятся
в схемалесс-бэге `settings` (JSON), поэтому новые автоматизации не требуют кода.

## Сущность Rule

Правила управляются через generic-админку сущностей (пункт **Rules** в меню,
`admin/rules.php`) и хранятся в таблице `rules` (миграция `010`). Аудит-журнал
находится в `rule_log` (миграция `011`).

Ключи settings (`entities/Rule.php`):

| Ключ | Тип | Назначение |
|------|-----|-----------|
| `enabled` | bool | Главный выключатель (по умолчанию true). |
| `schedule` | string | Частота — интервал / cron / макрос (см. ниже). |
| `timezone` | string | IANA-таймзона для cron и окна метрик. |
| `campaign_id` | int | Область метрик. `0` = все кампании. |
| `window` | string | Окно метрик: `today`, `yesterday`, `1h`, `24h`, `7d`, `30d`, `<секунды>`. |
| `match` | string | `all` (И) или `any` (ИЛИ) по условиям. |
| `conditions` | array | Список `{metric, op, value}`. Пусто = без условий. |
| `actions` | array | Список `{type, ...параметры}`. |
| `last_run` | int | Служебное: unix-время последнего запуска (ведётся автоматически). |

## Расписание (`rules/Schedule.php`, чистый класс)

Частоту задаёт одна строка:

- **Интервал**: `300` (секунды), `every:5m`, `every:2h`, `every:1d`.
- **Cron** (5 полей `m h dom mon dow`): поддержка `*`, списков `a,b`, диапазонов
  `a-b`, шагов `*/n`. `7` принимается как воскресенье.
- **Макросы**: `@hourly`, `@daily`/`@midnight`, `@weekly`, `@monthly`, `@yearly`.
- **Пусто**: запуск при каждом вызове планировщика.

`isDue($now, $lastRun)` — чистая функция с полным покрытием тестами.
Интервальные расписания сравнивают прошедшее время; cron-расписания сверяют поля
календаря в таймзоне правила и не срабатывают дважды в одну минуту.

## Условия (`rules/RuleEvaluator.php`, чистый класс)

Каждое условие — `{metric, op, value}`. Метрики берутся из `ReportAggregator`
Фазы 7: `clicks`, `uniques`, `bots`, `blocked`, `leads`, `purchases`,
`conversions`, `revenue`, `cost`, `profit`, `roi`, `cr`, `epc`, `cpc`, …
Операторы: `gt`/`>`, `gte`/`>=`, `lt`/`<`, `lte`/`<=`, `eq`/`=`, `neq`/`!=`.
Отсутствующая метрика считается равной `0`. `match` объединяет условия через И
(`all`) или ИЛИ (`any`).

## Действия (`rules/RuleActionExecutor.php`)

Действия диспетчеризуются по `type` к подключаемым обработчикам, поэтому будущие
фазы добавляют поведение регистрацией обработчика — без правок здесь (уведомления
Фазы 9 подключаются так же). Сбойное действие не прерывает остальные (каждое
обёрнуто, как и принято в политике «мягкой деградации» трекера).

Встроенные обработчики:

| Тип | Параметры | Эффект |
|-----|-----------|--------|
| `pause_campaign` | `campaign_id?` | Ставит кампании `enabled = false`. |
| `resume_campaign` | `campaign_id?` | Ставит кампании `enabled = true`. |
| `set_flow_weight` | `flow`, `weight`, `campaign_id?` | Меняет вес потока по имени. |
| `export_report` | `range`, `fields`, `group_by`, `format`, `output`, … | Пишет отчёт через экспортёр Фазы 7. Токены `output`: `{date}`, `{ts}`, `{ext}`. |
| `update_blacklists` | `feeds?` | Обновляет IP/UA-блэклисты Фазы 6. |
| `log` | `message` | Пустая запись в аудит. |

`campaign_id` по умолчанию берётся из `campaign_id` правила.

## Планировщик (`rules/RuleScheduler.php`)

`RuleScheduler::run($now)` загружает включённые правила, запускает те, чьё
расписание наступило, проверяет условия по окну `DashboardQuery` и выполняет
действия при совпадении. Каждый запуск двигает `last_run` и пишет строку в
`rule_log` (флаг совпадения, снимок метрик, результаты действий). Класс отделён
от пути запроса и покрыт тестами с in-memory драйвером и фейковыми
обработчиками.

## Точка входа cron

```
* * * * * php /path/to/YellowTDS/bin/run_rules.php >> /var/log/yatds-rules.log 2>&1
```

Запускать раз в минуту. Идемпотентность обеспечивается логикой интервала/cron и
полем `last_run`, поэтому правило не срабатывает чаще, чем настроено.

## Примеры правил

Пауза кампании при обвале ROI на значимом объёме:

```json
{
  "enabled": true,
  "schedule": "@hourly",
  "timezone": "UTC",
  "campaign_id": 12,
  "window": "today",
  "match": "all",
  "conditions": [
    {"metric": "clicks", "op": "gte", "value": 200},
    {"metric": "roi", "op": "lt", "value": -20}
  ],
  "actions": [
    {"type": "pause_campaign"},
    {"type": "log", "message": "paused on low ROI"}
  ]
}
```

Безусловное обслуживание по расписанию (пустые условия = всегда при наступлении):

```json
{
  "enabled": true,
  "schedule": "*/30 * * * *",
  "conditions": [],
  "actions": [
    {"type": "update_blacklists"},
    {"type": "export_report", "range": "today", "group_by": ["date","country"], "output": "exports/daily-{date}.csv"}
  ]
}
```

## Тесты

21 новых теста:

- `ScheduleTest` — единицы интервала, поля cron (шаги/списки/диапазоны),
  макросы, таймзоны, отсутствие повторного срабатывания в минуту.
- `RuleEvaluatorTest` — сопоставление И/ИЛИ, отсутствующая метрика как ноль,
  алиасы операторов.
- `RuleSchedulerTest` — seeded SQLite: запуск/выключенные/не наступившие
  правила, совпадение и его отсутствие, продвижение `last_run`, записи в
  `rule_log`, обработка неизвестного действия и исключений, разрешение окна.
