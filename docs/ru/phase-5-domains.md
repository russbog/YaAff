# Фаза 5: Домены + Cloudflare + пул доменов

## Обзор

Фаза 5 делает домены первоклассной переиспользуемой сущностью (как Источники,
Офферы и Сети) и добавляет опциональную автоматизацию DNS через Cloudflare.
Кампании по-прежнему хранят свой список `domains`, поэтому для существующих
кампаний ничего не меняется — пул доменов **дополняет**, а не заменяет:

- **Пул доменов** в админке (страница `Domains`), с группировкой.
- Поддержка **wildcard** (`*.example.com`) — через единый чистый матчер.
- **Алиасы**: доменный алиас может указывать на канонический хост; входящий
  запрос на алиас автоматически резолвится в канонический домен кампании.
- Интеграция с **Cloudflare API** для создания DNS-записей прямо из админки, с
  короткими таймаутами и детерминированным fallback (не блокирует ответ).

Всё управляется данными: атрибуты DNS/Cloudflare/алиасов лежат в JSON-поле
`settings` сущности — без хардкода под конкретный домен или аккаунт.

## Сущность

`Domain` (`entities/Domain.php`) следует стандартному соглашению: имя хоста
хранится в колонке `name`, остальное — в `settings`:

| Ключ           | Значение                                                      |
|----------------|---------------------------------------------------------------|
| `type`         | `regular` \| `wildcard` \| `alias`                           |
| `alias_of`     | канонический хост, в который резолвится `alias`              |
| `campaign_id`  | опциональная кампания, за которой закреплён домен            |
| `dns_type`     | `A` \| `CNAME` \| `AAAA` \| `TXT` (создаваемая запись)       |
| `dns_content`  | значение записи (IP для A/AAAA, целевой хост для CNAME)      |
| `dns_proxied`  | проксируется ли запись Cloudflare (оранжевое облако)        |
| `cf_zone_id`   | id зоны Cloudflare                                           |
| `cf_api_token` | scoped-токен Cloudflare (не логируется и не возвращается)    |
| `note`         | произвольная заметка                                         |

Миграция `db/migrations/009_create_domains.php` создаёт таблицу `domains` в том
же формате, что и остальные сущности.

## Сопоставление доменов и алиасы

`DomainMatcher` (`domains/DomainMatcher.php`) — чистый, покрытый тестами хелпер,
централизующий сопоставление хостов:

```php
DomainMatcher::matches(['*.example.com'], 'go.example.com'); // true
DomainMatcher::resolveAlias(['a.com' => 'b.com'], 'a.com');  // 'b.com'
```

`Db::get_campaign_by_domain()` теперь:

1. Строит карту алиасов из пула доменов (пустая, если таблицы нет, — старые
   установки продолжают работать).
2. Резолвит входящий хост через карту алиасов.
3. Сопоставляет кампании **и** с исходным, **и** с резолвнутым хостом.

Прежняя inline-логика wildcard в `Db::match_domain()` заменена тонким вызовом
`DomainMatcher::matches()` — поведение для существующих кампаний не изменилось.

## Автоматизация Cloudflare

`CloudflareClient` (`domains/CloudflareClient.php`) — generic-клиент Cloudflare
API. Построение запросов чистое; `send()` выполняет HTTP-вызов с таймаутами
`CONNECT_TIMEOUT = 2с` / `TOTAL_TIMEOUT = 3с` и **никогда не бросает
исключений** — при любой ошибке возвращает детерминированный конверт:

```php
[ 'ok' => bool, 'http_code' => int, 'error' => string, 'result' => array, 'raw' => string ]
```

Админ-эндпоинт `admin/cloudflare.php` предоставляет два действия по id домена:

- `?action=verify_token&id=N` — проверить сохранённый API-токен домена.
- `?action=create_record&id=N` — создать настроенную DNS-запись в зоне.

Учётные данные всегда читаются из настроек самого домена и никогда не
возвращаются в ответах.

## Обратная совместимость

- `settings['domains']` кампаний управляют сопоставлением ровно как раньше.
- Пул доменов и резолвинг алиасов — дополнение; при пустом пуле поведение
  идентично Фазе 4.
- Все вызовы Cloudflare деградируют мягко — сбой Cloudflare не влияет на
  обработку кликов.
