# Фаза 9: Уведомления (Telegram, Webhook, Email)

Фаза 9 добавляет настраиваемые алерты. **Канал уведомлений** — это
первоклассная сущность, управляемая данными (как Сети, Офферы, Правила):
вы описываете, *куда* уходит сообщение и *что* в нём, через плейсхолдеры
`{token}`. Никакого кода под каждую интеграцию.

Каналы запускаются по событиям. Движок правил из Фазы 8 вызывает их через
действие `notify`, но диспетчер универсален и может переиспользоваться другими
источниками событий (например, конверсиями) позже.

## Концепции

- **Канал** (таблица `channels`) — одна точка доставки. `type` выбирает
  транспорт: `telegram`, `webhook` или `email`. Все текстовые поля — это
  шаблоны с `{token}`, которые резолвятся при отправке.
- **События** — канал опционально подписывается на список имён событий
  (например, `rule`). Пустой список = получать все события. Действие `notify`
  может также явно указать каналы по id, минуя фильтр по событию.
- **Токены сообщения** — при срабатывании из правила доступны токены:
  `{event}`, `{rule}`, `{campaign}`, `{time}` плюс все метрики окна правила:
  `{clicks} {uniques} {bots} {blocked} {leads} {purchases} {conversions}
  {revenue} {cost} {profit} {roi} {cr} {epc} {cpc}`.
- **Аудит** — каждая попытка отправки пишется в `notification_log`
  (канал, тип, событие, ok, target, код, ошибка). Секреты, такие как токен
  Telegram-бота, не хранятся: в `target` лежит только обезличенный адрес.
- **Грациозная деградация** — транспорты используют жёсткие таймауты
  (connect 2с, total 3с) и никогда не бросают исключений; сбой доставки
  логируется, запуск продолжается.

## Типы каналов

### Telegram
- `bot_token` — токен бота из @BotFather (секрет; не логируется).
- `chat_id` — id чата / канала (токены допустимы).
- `parse_mode` — `HTML` (по умолчанию), `Markdown` или без.
- `message` — текст для отправки.

Отправляет `POST https://api.telegram.org/bot<token>/sendMessage` с
`chat_id` + `text`.

### Webhook
- `url` — эндпоинт (токены допустимы).
- `method` — `POST` (по умолчанию) или `GET`.
- `headers` — по строке `Имя-Заголовка=значение` (токены допустимы).
- `body` — шаблон тела; если пусто, используется шаблон `message`.
- `content_type` — добавляется автоматически для POST, если заголовок
  `Content-Type` не задан (по умолчанию `application/json`).

### Email
- `to` — получатели через запятую (токены допустимы).
- `from` — адрес отправителя.
- `subject` — шаблон темы.
- `message` — шаблон тела.

Использует PHP `mail()`; на хосте должен быть рабочий MTA.

## Запуск из правил

Добавьте действие `notify` в любое правило автоматизации (Фаза 8). Примеры:

```json
[
  {"type": "notify", "event": "rule", "message": "ROI {roi}% по кампании {campaign}"},
  {"type": "notify", "channels": [3, 5]}
]
```

- `event` (опц., по умолчанию `rule`) — выбирает подписанные на него каналы.
- `channels` (опц.) — явные id каналов; переопределяет фильтр по событию.
- `message` (опц.) — заранее отрендеренный текст, доступный каналам как
  `{message}`, поэтому шаблон канала может быть просто `{message}`.

Действие `notify` подключается в `bin/run_rules.php`, что оставляет исполнитель
действий Фазы 8 не связанным с модулем уведомлений.

## Файлы

- `entities/Channel.php` — сущность канала + типизированные аксессоры.
- `notifications/MessageRenderer.php` — чистый рендер `{token}` + `flatten()`.
- `notifications/ChannelSender.php` — построители запросов по типам (чистые) +
  I/O-транспорт (переопределяемый в тестах).
- `notifications/Notifier.php` — выбирает каналы, отправляет, пишет в
  `notification_log`.
- `db/migrations/012_create_channels.php`, `013_create_notification_log.php`.
- `admin/channels.php` + схема `channels` в `admin/entityschemas.php`.

## Админка

Откройте **Notifications** в навигации админки, чтобы создавать каналы. Форма
строится по схеме `channels`, поэтому добавление поля — это изменение данных.
